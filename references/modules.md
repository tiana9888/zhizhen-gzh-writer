# 智诊科技公众号写作八股模块库

定位：框架是骨，模块是肉。本库配套《智诊科技公众号内容框架-细化版》和《智诊科技公众号填空式写作模板》，保留八类模块，供按需选取、扩写和组合，不要求写成八个章节或固定四段。

默认路线是痛点、难点背景、解法措施、可选避坑、结尾。除标题后直接 3–5 问的开头要求外，可合并、拆分、重排或删除不相关模块，每个位置可用多个内容块。模块八贯穿校验，不单独占正文。

每个模块包含核心概念、常见问法、回答要点、适用场景和可填正文块。调用单个模块时应交付填好的内容块，不只复述规则。花括号均为待填位置，无材料的可选块直接删去。

## 模块一 · 标题设计

核心概念：把读者的具体问题与相关热点议题结合，不以虚构数字或夸大效果换取点击。

常见问法：目标机构正在处理什么问题？哪些热点与本文确实相关？标题承诺能否在正文兑现？

回答要点：每版标题至少含 3 个相关且经核实的热点词，优先覆盖技术、业务场景和读者关注点，不靠近义词堆叠凑数。参考 21–34 字，清晰优先；数字不是必需项。没有成效材料就写问题、动作或边界，不写客户已获得某种收益。交付 3–5 版不同角度标题，不使用无证据的绝对化词。

适用场景：场景问题式适合业务解读；数字结果式仅限有同口径实测证据；能力边界式适合产品介绍；反差式需真实存在反差，不制造假两难。候选术语不是天然热点，须核实相关性与热度。

可填标题块（各版组合至少 3 个相关热点词）：

```text
{{相关热点词组合}}怎么落地？{{目标机构}}先解决{{具体卡点}}
{{具体反差}}？{{相关热点词组合}}如何处理{{业务问题}}
{{真实对象}}采用{{相关技术议题}}后，{{实测变化及适用范围}}
{{相关热点词组合}}能做什么，{{具体环节}}还需确认哪些边界
```

## 模块二 · 痛点开场

核心概念：标题后不铺垫，直接用 3–5 个具体疑问句让读者识别自己的业务问题。

常见问法：谁在什么业务场景遇到什么卡点？问句是否具体到对象和动作？是否必须用数字才能说清？

回答要点：每问独立成行、以问号结束；场景和对象写在问句里。前面不得插入场景引子、开头小标题或引导句。有可靠材料才量化，数量按子问题决定，不按数字多少决定。问后可归拢共同环节，不固定归拢句。提炼痛点关键词，不限定四字。

适用场景：所有文章均用此开头；可不编号，也可用 1. 至 5.，按实际问数结束。后文章节另从“一”开始，不接续问句编号。

可填正文块（至少保留前三问，第 4、5 问按需补入；问句槽不含末尾问号）：

```text
{{目标机构}}在{{具体场景}}处理{{业务对象}}时，{{卡点1}}该由谁解决？
{{具体岗位}}面对{{业务对象与场景}}，怎样避免{{具体卡点2}}？
{{目标机构}}要完成{{业务任务}}，如何处理{{具体卡点3}}？
{{可选：场景、对象、卡点问句4}}？
{{可选：场景、对象、卡点问句5}}？
```

例如“交付慢、看不懂、定制贵、人力重”属于痛点关键词，不是四字词。具体疑问可以没有数字，不能只有“效率低吗”之类抽象标签。

## 模块三 · 难点解释

核心概念：解释卡点背后的具体约束，不靠制造两难来推动叙事。

常见问法：数据、流程或责任在哪一环断开？现有做法为何不足？代价是否有材料支撑？

回答要点：可写单一瓶颈、多个约束或真实两难。两难只在两个选择及代价均有依据时采用，不要求每篇都写。小标题概括具体判断，不能直接写“两难困境”。

适用场景：流程梳理可用原因链；选型讨论可用有依据的方案权衡；问题已解释清楚时可并入措施，不另占章节。

可填正文块：

```text
{{具体判断式小标题}}
{{业务卡点}}并不只发生在{{表面环节}}。在{{实际流程}}中，{{输入、责任或衔接约束}}使{{后续动作}}难以继续。
要处理这个问题，需要先明确{{前置条件}}，再安排{{对应措施}}。
```

真实两难变体：

```text
采用{{选项A}}需要承担{{有依据的代价A}}；采用{{选项B}}则受限于{{有依据的条件B}}。选择之前，应先核对{{决定条件}}。
```

## 模块四 · 背景与证据

核心概念：用相关材料支持具体判断，不强制证明行业加速或制造紧迫感。

常见问法：这份资料究竟证明了哪一句话？来源能否定位？研究、访谈或产品资料适用于什么范围？

回答要点：按相关性与证明力选行业资料、真实访谈、产品文档或机构实践；写清来源、时间及适用口径。公司资历不能代替效果验证，没有出处时删掉事实断言，不把“多数机构如此”改成无来源定性背书。

适用场景：可放在背景、措施或结果之后，允许多个证据块；没有合适材料时可删去独立背景段，但保留事实核验要求。

可填正文块：

```text
{{来源名称与时间}}针对{{对象、样本或场景}}记录了{{可核实事实}}。这项材料能够支持{{限定范围内的判断}}，但不能据此推断{{未被验证的结果}}。
```

产品材料变体：

```text
根据{{产品文档及版本日期}}，{{产品}}已支持{{已核实能力}}，适用条件是{{边界}}。{{规划能力}}仍属规划内容，不能写成已上线功能或客户实测成效。
```

## 模块五 · 能力、措施与成效

核心概念：写清如何处理问题、谁承担什么环节，以及结果的证据等级。

常见问法：输入是什么、动作是什么、输出交给谁？该措施回应哪个问句？描述的是已有能力、规划、预期收益还是实测结果？

回答要点：有真实案例可结果前置；无案例直接写能力说明或建议路径，不借匿名机构包装能力。建议聚焦 2–3 个主指标，不限制全文数字数量，必要的基线、样本量和时间照实保留。引语仅使用真实记录。涉及协作时，大模型承担医学理解与内容生成，智能体衔接数据、系统与流程；单个措施只写实际涉及的产品，不强制双产品同时出现。

适用场景：能力型可按新旧流程说明；方法型可列简洁编号步骤；升级型可做同口径对比。按主题选取和组合，不限定措施数量或固定先效率后体验的顺序。

可填正文块 A：已有能力或实施路径，无案例也可使用。

```text
{{具体动作或收益方向的小标题}}
在{{业务环节}}，{{已核实产品或人工角色}}对{{输入}}执行{{动作}}，将{{输出}}交给{{下游岗位或系统}}。
这一步针对的是{{开头子问题}}。{{如属建议路径则明确写“建议先……”；如属规划则明确标注“规划中”}}。
{{预期作用}}仍需通过{{试点方法与指标}}验证，不能作为已取得的成效。
```

可填正文块 B：真实案例与结果，仅在有材料时使用。

```text
{{真实且获准使用的客户或脱敏对象}}在{{时间与场景}}采用{{具体措施}}。
据{{可定位记录}}，在{{样本、基线与统计口径}}下，{{指标}}由{{原值}}变为{{结果值}}。该结果适用于{{范围}}，不外推至其他机构。
```

可填正文块 C：步骤与边界，可重复增减。

```text
1. {{动作1}}，把{{输入}}整理为{{输出}}，由{{责任角色}}确认。
2. {{动作2}}，处理{{子问题}}，遇到{{异常条件}}转交{{人工或系统环节}}。
{{产品分工与适用边界，只写实际涉及的环节}}。
```

真实引语附加块：仅从{{访谈或书面记录及日期}}摘录“{{原话}}”，注明可披露身份；无记录整块删除，不模仿客户口吻造句。

## 模块六 · 避坑与边界

核心概念：帮助读者核验方案和执行条件，而非暗设排他标准。

常见问法：哪些输入条件容易遗漏？异常由谁处理？验收标准能否对所有供应方一致适用？

回答要点：每块讲清现象、可能后果、核验或纠正方法。风险量化需证据；不写“只有智诊满足”“唯一方案”，不虚构竞品短板。条数不强制，允许并入措施。

适用场景：选型主题可独立展开；产品说明可改为常见问题；无相关内容则删除。短版仍保留必要的审核、数据或能力边界。

可填正文块：

```text
{{具体核验判断，例如“接入前先确认字段与审核责任”}}
如果{{常见做法或遗漏条件}}，可能出现{{具体后果及机制}}。实施前应核对{{通用验收标准}}，并通过{{验证动作}}确认。
```

常见问题变体：

```text
{{读者的具体顾虑}}？
{{有依据的回应}}。目前适用范围是{{边界}}，超出范围时需要{{补充验证或人工处理}}。
```

## 模块七 · 问题回收与下一步

核心概念：回应开头问题，给出有依据的判断和可执行的下一步。

常见问法：哪些痛点已有证据支持解决，哪些仍需验证？用户现在能做什么？资料和领取渠道是否真实存在？

回答要点：用痛点关键词回收，不限字数和固定句式；不得将全部问题宣称为已解决。可给试点建议，再根据真实条件选一个转化动作。资料包、服务、限额均须真实；没有就删，不承诺并不存在的交付物。

适用场景：每篇保留结论与问题回应，转化句可选，只能放结尾；删除转化句后正文仍完整。

可填正文块：

```text
回到{{痛点关键词}}，{{有证据支撑的判断}}；对于{{尚未验证的部分}}，应先完成{{验证动作}}。
{{一条可带走的结论或下一步建议}}。
{{可选：已备好的真实资料名称}}包含{{实际内容}}，可通过{{一个已确认的有效渠道}}获取。
```

## 模块八 · 排版与证据校验

核心概念：贯穿全文的检查层，不是第八个必写章节。

常见问法：开头是不是直接问句？章节编号是否独立？小标题能否概括具体判断？是否把预期写成事实？

回答要点：标题后立即 3–5 问，每句问号；可用问句编号 1. 至 5.，章节重新从“一”开始。正文允许“一、二”和节内“1. 2.”，禁表情、装饰和花式符号，不禁正常标点。小标题写具体判断或收益，不写“两难困境”“国家要求”等内部标签。单段原则上不超过 100 字，感叹号全文不超过 1 个。参考常规 2000–3000 字、短版 800–1500 字，不凑字数。

适用场景：所有组合均生效，专门检查开头前缀、章节编号、措施编号、证据等级及转化承诺。

可填排版块（用于已完成问句后的正文，不作为开头前缀）：

```text
一、{{本节具体判断}}
{{解释与相关证据}}。

二、{{本节具体动作或收益}}
1. {{措施及对应子问题}}。
2. {{措施及适用条件}}。
{{事实来源或待验证范围}}。
```

## 组合索引与自检

产品能力主题：模块一、二开头；三解释卡点，四提供可核实能力材料；五展开多个能力块，六补必要边界；七收束，八校验。没有客户材料时不插入案例块。

实施方法主题：模块一、二开头；三与四可合并；五按流程组织多个措施块，六可嵌入步骤；七给试点建议，八校验。

真实案例主题：模块一、二开头；可将五的实测结果前置到问句之后，再结合三、四解释约束与证据，展开措施及边界，最后用七回应问题。结果必须有可溯源材料。

以上是参考组合，不是强制次序。短版缩减展开深度，保留 3–5 问及必要边界；任何位置可放多块，内容可合并、拆分、重排或删除不相关部分。

成稿检查：标题相关热点词至少 3 个；开头直接 3–5 问；编号清晰且章节从一开始；小标题写判断或收益；痛点有回应；事实有来源；能力与成效不混写；引语有记录；没有虚构案例、限额或排他竞争承诺。
