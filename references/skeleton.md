# 智诊科技公众号内容框架 · 细化版

适用：面向医院、体检中心、检验机构决策者的智诊科技 B 端获客文章。

本文件是骨，规定文章推进路线、证据边界和组装方法；《智诊科技公众号写作八股模块库》是肉，提供可填正文块；《智诊科技公众号填空式写作模板》是配套操作模板。八个模块是素材分类，不是八个必写章节，也不限定四段数量。

## 一、总原则

1. 一篇围绕一个核心业务问题，可展开多个相关子问题；案例按材料选用，不强制出现，结尾最多推动一个转化动作。
2. 标题之后立即写 3–5 个具体疑问句，每句独立成行并以问号结束。前面不加场景引子、开头小标题、介绍或引导句。
3. 把场景、对象和业务卡点写进问句。有可靠材料才量化，无数字也能写清具体问题，不为凑数字减少必要问句。
4. 默认沿“痛点、难点背景、解法措施、可选避坑、结尾”推进。可合并、拆分、重排或删除不相关模块，每个位置可容纳多个内容块；标题后直接问句的顺序不变。
5. 事实与数字必须可核验；区分已实现能力、规划能力、预期收益和实测成效。没有证据，不把方案描述包装成已落地案例。

## 二、排版规范

| 项目 | 标准 |
|---|---|
| 开头 | 标题后直接 3–5 问，无开头小标题、场景引子或引导句；可不编号，也可按实际数量标为 1. 至 5. |
| 编号 | 允许清晰简洁编号：一级“一、二、三”，节内“1. 2. 3.”；开头问句编号与章节编号分开，问句结束后章节从“一”开始 |
| 符号 | 禁止表情、装饰和花式符号；正常标点、书名号、括号及简洁编号可以使用，不用符号堆叠制造层级 |
| 小标题 | 概括具体判断或收益，如“先统一数据口径，再谈自动生成”；不用“两难困境”“难点背景”“结果措施”“国家要求”等内部结构标签充当成稿标题 |
| 段句 | 一段一个意思，单段原则上不超过 100 字；优先短句，不机械拆碎完整意思 |
| 强调 | 按需加粗结论或关键数字，不整段加粗，不强凑金句和加粗数量 |
| 篇幅 | 常规版参考 2000–3000 字，短版参考 800–1500 字；按材料与问题复杂度调整，不为字数填充 |
| 情绪与转化 | 感叹号全文不超过 1 个；开头不报家门、不引导关注或加群；转化引导只放结尾，删除引导后正文仍完整 |

## 三、标题

标题至少含 3 个与主题相关、可确认的热点词或热点议题关键词，优先兼顾技术、业务场景和读者关注点。先核实相关性与热度，再选词；不能为满足数量硬塞品牌、拼造热点。材料不足时补充核实，未满足前不标为可发布标题。

候选词仅用于检索和选题，不自动等于当前热点：大模型、智能体、AI Agent、AI 医疗、体检中心、检验科、体检报告、报告周转、人效、质量审核。近义词堆叠不算三个独立议题。

可选公式，不固定一种：

1. 反差疑问：{{具体反差}}？{{相关热点词组合}}如何处理{{业务问题}}
2. 场景问题：{{目标机构}}遇到{{具体卡点}}，{{相关技术议题}}该先改哪一环
3. 实测结果：{{真实对象}}采用{{相关技术}}后，{{有来源的变化}}
4. 能力解读：{{相关热点词组合}}能做什么，{{具体业务环节}}还需确认哪些边界
5. 决策判断：{{相关热点词组合}}怎么选，先核对{{关键条件}}

标题参考 21–34 字，清晰优先；不强制数字，具体问题或变化也可形成钩子。只有真实材料支持，才能使用客户身份、采用事实或成效。禁止无证据的“首个”“唯一”“彻底”等绝对化表述，不踩一捧一。交付 3–5 版备选，尽量覆盖不同切入角度，每版单独核查热点词与事实。

## 四、正文默认路线

以下名称用于写作组织，不直接充当成稿小标题；章节数量按内容决定。

### 痛点：用问题直接进入业务

标题后连续写 3–5 个具体疑问句，场景和对象包含在句内。例如“体检中心集中出报告时，跨系统的异常指标由谁核对？”问句数量按子问题确定，不按可用数字多少决定。

问句写完后，可用一句话归拢共同业务环节，也可直接进入解释；归拢句不是固定件，更不能挪到问句之前。提炼“交付慢、看不懂、定制贵、人力重”等痛点关键词供后文回应，不称“四字词”，不限定字数。

### 难点与背景：解释问题为什么发生

说明具体约束，如数据口径不一致、审核责任不清、流程衔接中断。真实存在两种选择及各自代价时才用两难写法，不制造“快与准只能二选一”的假对立。

相关行业材料、客户访谈、产品资料可嵌入解释；按相关性和证明力选用，不强制独立背书段或固定优先级。不要求所有资料都证明需求加速，更不能用公司资历替代效果证据。没有材料时删掉无法证实的行业判断，或明确写成待核实的问题。

### 解法与措施：写清动作、作用和边界

有真实案例及结果时可结果前置，交代对象、场景、时间、口径与来源；没有案例时直接讲已核实能力或建议实施路径，不写“破局样本已经出现”。

每个措施块说明：处理什么输入、执行什么动作、输出交给谁、对应哪个痛点，以及适用条件或待验证指标。可按流程、能力、对比等方式展开，也可在不同内容块中组合使用；数量和顺序按问题决定。

涉及两类产品协作时，统一分工为“大模型承担医学理解与内容生成，智能体衔接数据、系统与流程”。具体措施只写实际涉及的产品，不要求每个措施同时出现大模型与智能体；其他人工、审核或系统环节也应如实保留。

建议聚焦 2–3 个主指标，便于读者理解，不是全文数字上限。其他必要日期、样本量、基线及统计条件照实保留。前后对比必须同口径；没有实测结果时写“拟验证”“目标是”或“预期作用”，不可改写为“已提升”。客户引语只用真实访谈或书面记录，无法核实则删除，不代写客户评价。

### 可选避坑：给出可核验的执行标准

按需写现象、可能后果、核验或改进方法。风险无法量化就解释具体机制，不编损失数字。标准对所有供应方一致适用，不写“只有智诊满足”“唯一方案”，不暗设无证据的排他门槛。

可改为注意事项或常见问题，也可并入措施段、整体删除；短版仍可保留必要边界，不机械删掉风险说明。

### 结尾：回收问题并给出下一步

回应开头的痛点关键词：哪些已有证据支持、哪些需要试点、哪些不在本次方案范围内，不默认所有问题都已解决。给出一个可带走的判断，再按实际条件选择一个转化动作。

仅在资料和渠道确实存在时，写领取内容、联系人或后台回复方式；没有资料就不许诺资料包，没有真实安排就不写限额、赠送诊断或稀缺名额。转化句删去后，结论仍成立。

## 五、篇幅与材料分配

开头只用 3–5 问完成进入，不铺垫长场景。篇幅优先留给措施、证据和适用边界；背景足以解释问题即可。一个章节可包含多个措施块，一个材料块也可嵌入不同论证位置，但避免重复。

常规版与短版共享硬要求，仅调整展开深度，不以“必须八模块”“必须四段”“每槽一个模块”决定结构。

## 六、发布前自检

1. 标题是否至少含 3 个相关且可确认的热点词，未拼造热点或成效？
2. 标题后是否立即出现 3–5 个具体问句，每句以问号结束，前无引子、小标题和引导句？
3. 场景、对象、卡点是否写入问句，量化是否有可靠材料？
4. 开头如有编号，后文章节是否独立从“一”开始？正文是否仅使用简洁编号与正常标点？
5. 小标题是否概括具体判断或收益，而非内部结构标签？
6. 模块取舍是否服务主题，未强制八模块、四段或每位置单块？
7. 措施是否回应问题并写清实际产品作用、人工责任与适用边界？
8. 数字、案例、引语是否可溯源，规划能力、预期收益与实测成效是否分开？主指标是否聚焦且对比口径一致？
9. 是否删除无证据的排他竞争表述、虚构案例、资料包和限额？
10. 结尾是否如实回应痛点，转化渠道是否真实，删除转化句后正文是否完整？

## 八、骨架与模块组装机制

| 骨架位置 | 可调用模块 | 组装说明 |
|---|---|---|
| 标题 | 一：标题设计 | 每个候选标题分别核验关键词及承诺 |
| 标题之后 | 二：痛点开场 | 固定 3–5 问直入，可编号；不得在前面插入其他块 |
| 难点与背景 | 三：难点解释；四：背景与证据 | 可合并、拆分或将证据嵌入措施，不强制独立背书 |
| 解法与措施 | 五：能力、措施与成效；四：证据 | 按材料选择多个正文块，不强制案例或双产品同现 |
| 选型与执行提醒 | 六：避坑与边界 | 可独立、并入措施或删除无关内容 |
| 结尾 | 七：问题回收与下一步 | 保留有依据的结论；转化动作按真实条件添加 |
| 全文检查 | 八：排版与证据校验 | 校验层，不是必须写进文章的章节 |

组装步骤：先明确核心问题和可靠材料，再列出 3–5 个问句；按默认路线挑选可填正文块，每处可放多块；根据论证需要合并、拆分、重排、删去无关内容；最后改成具体小标题并核验。

咬合检查：问句应得到回应或明确范围；措施必须对应真实卡点；指标口径一致且有出处；产品作用与材料一致；结尾不超出证据承诺。不能靠虚构案例、引语、数字或稀缺名额补齐结构。
